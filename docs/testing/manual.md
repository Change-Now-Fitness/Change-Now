Case 1 — Create account: Open the app’s login screen, go to sign-up, enter a new email, a password of at least six characters, and matching confirmation, then submit; with the backend running and reachable from the client, you should see success in the browser console (and related network calls succeeding) and the app should navigate to the main dashboard, and you can optionally confirm the new row appears in your users table in Supabase.

Case 2 — Log in: From a clean session, open the login screen, enter the same email and password you used when the account was created, submit; the app should call the login endpoint successfully, set session as intended for your platform, and take you to the main dashboard, while wrong credentials should leave you on the login flow with failed requests visible in the console or network tab.

Case 3 — Record a workout set: While logged in, open the exercise library, pick an exercise and open its detail/selected screen, enter valid numeric weight and reps, then add the set; the client should POST to the workouts/sets API successfully, the new set should appear in the UI, and when you reload or revisit that screen the history (or chart) should reflect the saved data, whereas invalid or empty inputs should not persist a set.
